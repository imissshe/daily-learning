# 2026-11-20 学习笔记：git cherry-pick

今天学了 `git cherry-pick`：它可以把另一个分支上的某个提交单独"摘"过来，应用到当前分支，而不用把整个分支合并进来。

最常见的场景是：修复 bug 的提交先合进了主分支，又想把它同步到发布分支时，直接 `git cherry-pick <commit>` 就能把那一次改动原样搬过去，历史记录里还会保留原来的提交信息。

如果摘过来的提交和当前分支有冲突，Git 会停下来等你手动解决，解决后 `git cherry-pick --continue` 继续；中途想放弃就用 `--abort` 回到开始前的状态。

一个小提醒：cherry-pick 会生成一个新的提交哈希，即使内容完全一样，所以事后别再去合并原来那个分支，否则可能出现重复提交。
