# Git 撤销操作速查：restore / reset / revert / reflog

> 2026-10-29 · 📝 学习笔记 · Git

写错了、提交错了、甚至 `reset --hard` 删错了，Git 基本都能救回来。关键是先搞清楚：**改动现在在哪一层？这个提交推送（push）过没有？**

## 三个区域

| 区域 | 说明 | 查看 |
|---|---|---|
| 工作区 working tree | 你正在编辑的文件 | `git diff` |
| 暂存区 index / staging | `git add` 之后、等待提交 | `git diff --staged` |
| 仓库 repository | 已经 `git commit` 的历史 | `git log` |

## 场景 → 命令

| 我想…… | 命令 | 会丢东西吗 |
|---|---|---|
| 丢弃某个文件在工作区的改动 | `git restore <file>` | ⚠️ 会丢掉未提交的改动 |
| 取消暂存（改动留在工作区） | `git restore --staged <file>` | 不会 |
| 改一下最近一次提交的信息/补个文件 | `git commit --amend` | 不会（但改写了历史） |
| 撤销最近提交，改动回到**暂存区** | `git reset --soft HEAD~1` | 不会 |
| 撤销最近提交，改动回到**工作区** | `git reset HEAD~1`（默认 `--mixed`） | 不会 |
| 撤销最近提交并**彻底丢弃**改动 | `git reset --hard HEAD~1` | ⚠️ 会（但可用 reflog 找回已提交的内容） |
| 撤销一个**已推送**的提交 | `git revert <commit>` | 不会，新增一个反向提交 |
| 找回“丢失”的提交 | `git reflog` → `git reset --hard <sha>` | — |

## reset 和 revert 怎么选？

- **reset**：移动分支指针，*改写历史*。只适合还没推送、只有自己在用的提交。已推送的再 reset，需要 `push --force`，会坑到协作者。
- **revert**：生成一个新提交来抵消旧提交，*历史只增不减*。公共分支（如 `main`）上撤销请用它。

## reflog：后悔药

`git reflog` 记录了 HEAD 每一次移动（commit、reset、checkout、rebase……），默认保留约 90 天。`reset --hard` 删掉的提交，只要曾经提交过，就能在 reflog 里找到：

```bash
git reflog              # 找到想回去的那一行，比如 HEAD@{1}
git reset --hard HEAD@{1}
```

注意：**从未 add/commit 过的工作区改动**，reflog 救不回来——所以 `git restore` 和 `reset --hard` 前先 `git status` 看一眼，或者先 `git stash`。

## 可运行示例

在临时目录里跑，不会影响任何现有仓库（已用 Git 2.47 实测，注释是实际输出）：

```bash
set -e
cd "$(mktemp -d)" && git init -q -b main && git config user.name demo && git config user.email demo@example.com
echo v1 > a.txt && git add a.txt && git commit -qm "v1"
echo v2 > a.txt && git commit -qam "v2"
echo v3 > a.txt && git commit -qam "v3"

# 1) 丢弃工作区改动
echo oops > a.txt && git restore a.txt && cat a.txt              # v3

# 2) 取消暂存（改动保留在工作区）
echo staged > a.txt && git add a.txt && git restore --staged a.txt
git status --short                                                # " M a.txt"
git restore a.txt

# 3) reset --soft：撤销最近一次提交，改动留在暂存区
git reset --soft HEAD~1 && git status --short                     # "M  a.txt"
git commit -qm "v3 again"

# 4) revert：新增一个“反向提交”，不改写历史
git revert --no-edit HEAD >/dev/null && cat a.txt                 # v2
git log --oneline | wc -l                                         # 4

# 5) reset --hard + reflog 找回
git reset -q --hard HEAD~3 && cat a.txt                           # v1（“误删”了 3 个提交）
git reset -q --hard 'HEAD@{1}' && cat a.txt                       # v2（revert 后的状态）
git log --oneline | wc -l                                         # 4
```

## 小结

1. 没提交 → `restore`；提交了没推送 → `reset`；已经推送 → `revert`。
2. `--hard` 和 `restore <file>` 是仅有的两个会真正丢掉未提交改动的操作，用前三思。
3. 提交过的东西几乎不会真丢，记住 `git reflog`。
